# 사용 설명서 (자세한 실행법·체계·데이터)

> 프로젝트 소개는 [../README.md](../README.md)에 있어요.


> **[정통 계산] 사주·자미두수·점성술의 전통 공식 그대로 계산한 상세 해석입니다.**
> 생년월일·태어난 시간·성별·도시는 **메모리에만** 두고 파일에 저장하지 않습니다.
> 계산은 전부 로컬이라 비행기 모드에서도 동작합니다. 웹 채팅만 구독 AI 모델을
> 로컬 CLI 명령으로 부르고, 없으면 로컬 규칙 에이전트가 답합니다.
> 사용 범위: 1900~2049년생.

## 설치

의존성 없음(표준라이브러리만). Python 3.10+:

```bash
uv run --python 3.14 python -m love_fortune --birth 1990-05-15 --birth-time 12:00 --sex male --city 부산
```

## 실행법

```bash
# 오늘 리포트 (터미널 + report_YYYYMMDD.md 저장, 개인정보 제외)
python -m love_fortune --birth 1990-05-15 --birth-time 12:00 --sex male --city 부산

# 영역 선택 (total=총운, love=연애, career=직장, money=금전, all=전체)
python -m love_fortune --birth 1990-05-15 --domain money --no-save

# 평생 운세 타임라인 추가 (연대별 0~89세 + 올해 기준 전후 11년)
python -m love_fortune --birth 1990-05-15 --lifetime --no-save

# 태어난 시간을 모르면 '모름' (시주 제외·자미/하우스 제외, 3기둥 + 정오 어림 병기)
python -m love_fortune --birth 1990-05-15 --birth-time 모름 --no-save

# 음력 생일로 입력 (윤달이면 --leap 추가). 성별은 남/여로 써도 된다
python -m love_fortune --birth 1990-04-21 --calendar lunar --sex 여 --city 부산 --no-save

# 해외 출생은 현지 시각 그대로 (현지 서머타임 자동 반영)
python -m love_fortune --birth 1990-07-04 --birth-time 09:00 --city 뉴욕 --no-save

# 두 사람 궁합 (대칭 점수, 개인정보 제외 저장)
python -m love_fortune match --birth 1990-05-15 --birth2 1997-06-15 --no-save

# 길일 고르기 (기간 내 일자별 랭킹, 목적별 정렬)
python -m love_fortune pick --birth 1990-05-15 --from 2026-10-01 --to 2026-10-31 --domain love --no-save

# 내일 리포트
python -m love_fortune --birth 1990-05-15 --sex male --city 부산 --tomorrow

# 대화형 입력 모드 (인자 없이 실행해도 이 모드로 진입)
python -m love_fortune --interactive

# 로컬 브라우저 입력폼 (이 컴퓨터에서만 열림, 입력값 저장 안 함)
python -m love_fortune form
# → http://localhost:8765  (홈페이지식 UI + 리포트 카드 + 채팅 상담 에이전트)
# 휴대폰 등 다른 기기에서 보려면: python -m love_fortune form --host 0.0.0.0
# (watchdog.py 는 이 옵션으로 띄운다. 같은 와이파이의 기기에서 http://<이 PC IP>:8765)

# 특정 날짜 재현 (테스트·디버그용)
python -m love_fortune --birth 1990-05-15 --date 2026-09-20 --no-save

# 테스트
python -m pytest
```

## 설정 (.env)과 Supabase 연결

설정은 프로젝트 폴더의 `.env` 에 적는다 (git 에 안 올라간다). 적는 법과 항목은 `.env.example` 에 있다.
배포(Render)에서는 `.env` 대신 Render 대시보드 > Environment 에 같은 이름으로 넣는다.

Supabase 에 공유 링크·AI 풀이를 저장하려면:

1. supabase.com 에서 프로젝트를 만든다. 지역은 서울(Northeast Asia, Seoul)을 고른다.
2. 대시보드 > SQL Editor > New query 에 `db/supabase.sql` 내용을 붙여 넣고 Run. 표 두 개(chapter, share)가 생긴다.
3. Project Settings > API 에서 두 값을 복사해 `.env` (또는 Render Environment)에 넣는다.
   - `SUPABASE_URL`: Project URL (https://xxxx.supabase.co)
   - `SUPABASE_SECRET_KEY`: Secret key (sb_secret_...) 또는 예전 화면의 service_role 키. anon/publishable 키가 아니다.
4. 서버를 다시 켠다. `/healthz` 가 `{"ok": true, "store": "supabase"}` 로 나오면 연결된 것이다.

값을 비워 두면 지금처럼 로컬 SQLite(`data/content.db`)에 저장한다.
Supabase 무료 프로젝트는 7일 동안 요청이 없으면 일시정지되니, 멈추면 대시보드에서 다시 켠다.

## 오늘의 운세를 보는 방식

오늘 운세는 세 체계와 한국 택일을 함께 본다 (`today.py`). 리포트 맨 앞의
**오늘 세 체계 종합**에 체계별 신호(좋음·보통·조심)와 합의 여부가 나온다.

| 체계 | 오늘을 보는 층 |
|---|---|
| 사주 | 오늘 일진과 원국의 합충·십신, 오늘 일간의 십이운성, 오늘 드는 신살(천을귀인·도화·역마·공망), 억부 용신 기준으로 오늘 기운이 돕는지 |
| 자미두수 | 유일(오늘)·유월(이번 달) 궁과 사화가 내 명반 어느 영역에 붙는지 (두군법, iztro 1,335건 일치) |
| 점성술 | 오늘 하늘 행성이 출생 행성과 이루는 각도(트랜짓), 달이 지나는 하우스, 역행 행성 |
| 택일 | 생기복덕(천기대요), 건제12신, 황도·흑도, 손 없는 날, 월기일, 충, 28수(이름만) |

점수에 섞여 있던 날짜 해시 잡음(±5점)은 뺐다. 30일 일운·12개월 월운은 '이번 달·올해 흐름'
(웹은 '기간' 탭)으로, 출생 차트·명반은 '타고난 명식'(웹은 '명식' 탭)으로 나눴다. 타로·주역 같은
날짜 해시 점괘는 '재미로 보는 점괘'로 내리고 계산과 무관하다고 표시한다.

## 데이터와 출처

- 해석 데이터는 `db/init.sql`(SQLite)에 있다. 앱이 처음 실행될 때 `data/fortune.db`를 자동으로
  만든다. DBeaver 등으로 `data/fortune.db`를 열어 볼 수 있고, `source` 테이블에 출처와 검증 방법이 있다.
- 24절기 시각은 NASA JPL DE421 천체력으로 계산해 내장했다 (`tools/gen_solar_terms.py`).
- 외부 기준과의 대조 스크립트는 `tools/reference/`, 고정 대조 데이터는 `tests/data/`에 있다
  (한국천문연구원, lunar-python, iztro, 궁합닷컴 생기복덕 조견표).
- 밤 11시~12시 출생은 학계·사이트마다 기준이 달라 선택하게 했다: `--zi next`(정자시, 기본) / `--zi split`(야자시).

  위쪽 '저장·공유' 버튼: 다시 보기 링크(/r/<id>, 계산 결과만 저장)와 지금 탭의 이미지 카드(PNG, 휴대폰은 바로 공유).
  그림(명반·차트·상생도·카드)은 모두 SVG·캔버스로 그려 GPU 를 쓰지 않는다.

  나이는 만 나이로 보인다. 생기복덕·자미두수처럼 세는나이를 쓰는 전통 계산은 문장에 '세는나이'라고 적는다.
  - 계산 부품 (바로 뜸): 원국 표(십신·지장간·12운성·오행 막대·신살·귀인), 오늘 점수 게이지,
    세 체계(사주·자미두수·점성술) 신호, 오늘 택일, 띠 궁합, 12개월 시그널 캘린더(누르면 이유),
    3년 흐름, 연대별 타임라인
  - 기본 풀이 (바로 뜸, 약 1초): 계산 결과 문장을 챕터 흐름에 맞게 엮은 풀이 (`rule_chapters.py`).
    모든 챕터가 입력 직후 채워진다.
  - AI 풀이 (준비되는 대로 바꿔 끼움): 구독 AI 모델이 그 챕터에 필요한 **계산 결과(사실표)만**
    보고 쓴다. 사실표에 없는 것·확률·단정 예언은 쓰지 않게 막고, 결과는 `data/content.db`에
    저장해 같은 사주는 다시 부르지 않는다. AI 를 못 쓰면 기본 풀이가 그대로 남는다.
    마지막 거름망(`chapters.ground`)이 사실표에 없는 숫자(날짜·나이·개월 수)나 '반드시' 같은
    단정 표현이 든 문장을 화면에 내보내기 전에 뺀다.
  - 미리 만들기 (`prefetch.py`): 입력하자마자 모든 탭의 AI 풀이를 총운부터 대기열에 넣고,
    화면이 연 탭의 챕터를 맨 앞으로 당긴다. 새 사람 한 명당 AI 호출이 최대 33번 생긴다 (챕터 수만큼).
    끄려면 `SAJU_PREFETCH=0` (연 탭만 만든다).
- 맨 아래 **AI 상담**: 리포트를 아는 상담 에이전트와 대화 (구독 AI 모델, 실패 시 로컬 규칙 에이전트)
  - 도구는 전부 끄고, 대화는 저장하지 않으며, 생년월일을 뺀 요약만 보낸다.
  - 모델·명령: 환경변수 `SAJU_AI_MODEL`(기본 claude-sonnet-5), `SAJU_AI_CLI`
  - 동시에 도는 AI 호출 수: `SAJU_AI_PARALLEL`(기본 3, 미리 만들기는 한 자리를 상담용으로 남긴다).
    `SAJU_AI=0` 이면 AI 없이 기본 풀이만.
  - 채팅 API(`/api/chat`)에 `backend=openai`·`endpoint`·`api_key` 를 주면 OpenAI 호환 LLM(예: Ollama `http://localhost:11434/v1`)도 부를 수 있다.
    요청이 준 주소로 서버가 요청을 보내는 기능이라 공개 서버에서는 위험해서(SSRF), `SAJU_CUSTOM_LLM=1` 일 때만 켜진다.

### AI 연결 방식 바꾸기 (공개 서비스용 OpenRouter)

기본은 이 PC 에 로그인된 구독 AI 를 CLI 로 부른다. 서비스로 공개할 때는 OpenRouter API 로 바꾼다.

```bash
SAJU_AI_BACKEND=openrouter
OPENROUTER_API_KEY=...                     # OpenRouter 에서 발급한 키
SAJU_OPENROUTER_MODEL=제공사/모델   # OpenRouter 모델 이름 (필수, 기본값 없음)
```

- 키나 모델 이름이 없으면 AI 를 끈 것으로 보고 기본 풀이만 보여 준다.
- 보내는 내용은 CLI 방식과 같다 (개인정보를 뺀 계산 결과와 요청). 챕터 저장 키에 모델 이름이 들어가서,
  모델을 바꾸면 풀이를 새로 만든다.

### 이름 풀이 데이터

- `love_fortune/name_hanja.json`: 대법원 인명용 한자 9,904개(음별)의 훈음과 원획. `tools/gen_name_hanja.py` 로 만든다
  (Unicode Unihan 16.0 부수·획수 + rutopio/Korean-Name-Hanja-Charset(MIT) 대법원 목록·훈음). 한자 대신 코드포인트로 둔다.
- 원획: 강희 부수 원래 획수 + 나머지 획수, 숫자 한자는 그 수. 인터넷 한국작명연구원이 꼽은 틀리기 쉬운 33자와 모두 같다.
- 81수리 길흉은 네 곳 작명 자료를 대조한 다수결 (72수 일치, 78 은 엇갈림).

### 데이터베이스 파일

- `db/init.sql` → `data/fortune.db`: 검증한 기준 데이터 (생기복덕표 등). 첫 실행 때 자동 생성.
- `db/content.sql` → `data/content.db`: AI 챕터 풀이 저장소. 개인정보 없이 계산 결과 해시로만 찾는다.
  둘 다 DBeaver 등에서 SQLite 로 열어 볼 수 있고, 지워도 다음 실행 때 다시 만들어진다.
